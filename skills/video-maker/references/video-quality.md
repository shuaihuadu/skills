# 画面、字幕与成片验收

## 逐镜选表现手法

先问「观众需要看到什么变化或细节」，再选媒介。对最重要的一镜可试两种真正不同的拍法，例如固定机位做前后对照，或跟随一个对象再拉远看整体，而不是同一画面换配色。先放主体，再放标注；除非正在展示真实界面，不把视频画面布置成常驻页眉、按钮和面板组成的网站。

| 观众要看见什么 | 优先考虑 |
| --- | --- |
| 内外结构、装配顺序、遮挡、地形高差或空间路径 | 用 Three.js 做真 3D，或用已有实拍、预渲染镜头。先给全貌，再换到能揭示新信息的视角；拆解优先沿装配轴，读数时停稳。 |
| 平面流程、数据变化、对比、标注和信息图 | 用 SVG、DOM 或 Canvas 2D。固定参照，直接标值；颜色之外保留位置、形状或文字线索，不靠透视判断大小。 |
| 软件操作、代码、作品或实物细节 | 用真实界面录制、截图或获准使用的实拍和图片，从定位切到细节；只高亮当前对象。生成或模拟素材不冒充实拍、实测。 |
| 表演、音乐、氛围或抽象动效 | 让原始素材、动作、节拍、乐句或有意的静止带节奏；按观看目标选择混剪、生成素材或程序动效，不要求人声或剧情式开场。 |

可以混用，例如 3D 讲结构、二维标注给名称、静止剖面让观众读数。需要人物全程在画面里时，保持人物层贯穿时间线，按镜头调整构图；这只是明确要求时才用的拍法。

使用 Three.js 时按 HyperFrames 的 `hf-seek` 驱动相机、对象和着色器，画面只由给定时间和固定种子决定；在渲染前等本地模型、纹理、字体等必要资源就绪。先用实际渲染环境试最复杂的镜头；WebGL 不可用时，优先用预渲染素材或能表达同一关系的二维剖面，不交付黑画布。

## 关键镜头与节奏

- 第一帧能认出主体，开头尽快给出具体问题、冲突或结果。每幕只突出一件事：演示用对照和变化讲清因果，教程显示实际操作和结果，故事让动作推进情节。结尾兑现开场问题；不要用装饰动画、重复页眉或满屏旁白填满停留时间。
- 同一物件、标注和颜色在前后镜头指同一件事。标注贴近被解释的物件，关键变化、数值和高亮在旁白说到时出现。演示图按模型或可核查数据制作，标好单位、参考系或示意性质；必要时用静态示意替代不准确的动效。
- 先看一小段从铺垫到结果的连续样片。对靠画面说明的镜头，静音并暂时遮住解说文字，保留对象、代码和数据，检查动作或对照本身是否提供证据；靠音乐、同期声或对白叙事的镜头按原声检查。再用目标观看尺寸和正常速度看主体、字幕和数值是否有空间、来得及读。重点查空帧、裁切、遮挡、缺字和方向冲突；解决这些问题再加装饰或转场。

## 无底色字幕

- 用实际旁白的字词或句级时间戳，不按文稿字数估算整片。只有句级时间戳时按意群细分，再逐段抽听或核对波形与画面。审对专有名词、数字和单位；同一时间只显示一组。字幕不得提前泄露答案，也不能在讲话结束后长时间悬挂。
- 单行优先，最多两行，同一画幅保持稳定的下沿、字级和对齐。按语言的阅读习惯断行；长句先拆成连续两组，不把词组、数值和单位拆开，也不一味缩字。用正常速度审读，留够时间。样片覆盖最长行、最快一句、开场和切点前后。
- 仅用白字、深色描边和可选的轻微阴影，不加底色、色块或横条。不同明暗底都要能读；描边不能吃掉字心。复杂背景先调整字幕周围构图或轻换位置，不以加底色代替调构图。
- 安全区看的是最终画面中**整块字形和描边**，不是容器坐标。按目标平台核对底部简介、右侧操作列和裁切；双平台共用一版时取两个安全区的交集，贴近交集的下沿放置。能看到真正的播放预览就用它核对。没有公开预览时，用已知平台遮罩或保守参考，不为检查而上传。
- 若缺少可靠平台布局，竖屏 1080 × 1920 用 HyperFrames 社交竖屏指南的 `y=1330` 作为暂定文字下边界，不把它当平台固定规格，也不套用旧项目的像素值。用约 360 像素宽的预览加遮罩复查，长文案界面留更多余量。交付注明哪些只按估算遮罩检查，不能声称已验证上线效果。

## 音轨与导出

- 按项目检查主音轨：有旁白或对白时优先保证它听得清，检查音色、专名、数字和切点有没有吞字、断音或串场；音乐主导时检查乐句、拍点、响度和收尾；明确静音时核对无意外声音或轨道。许可记在独立资料文件。不方便听审时，用各段时间戳、响度、真峰值及静音检测辅助，并明确没有人工听审。
- 运行 `hyperframes check --json`。错误先修；安全区、缺字、低对比、音画错位等提示用实际预览核对，未解决的可读性问题不能忽略。用 `hyperframes snapshot --review` 或等效方式看手机尺寸图、关键变化前后和切点，按 HyperFrames 流程打开可编辑预览。
- 默认交付确认尺寸和帧率的 H.264 MP4，有音轨时用 AAC。用 `ffprobe` 核对编码、尺寸、帧率、时长和音轨。从**最终 MP4** 解码抽查首帧、核心动作前后、最难读的文字、转场和结尾。有动作的镜头取两个有判别力的时间点，确认主体区域按预期变化，不把字幕变了当作画面没冻结。再按正常速度连看关键段，确认观众能从动作、细节或对照找到证据；静止镜头按其预期检查。需要封面时取一张主体完整且没有旁白字幕的图，核对平台裁切。最终文件不通过则保留上一个可用成片，修复后再替换。
