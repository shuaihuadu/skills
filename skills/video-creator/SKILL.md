# Video Creator 视频创作技能

创建专业的短视频，包含动画场景、TTS 语音旁白和字幕。每个视频的视觉风格由 AI 根据主题量身定制。

## 概述

此技能通过以下步骤生成 1-3 分钟的 MP4 视频：

1. 先写并展示讲解大纲：讲给谁、回答什么、分几步、最后能学会什么。再为每一步选证据和拍法。
2. 合成语音和 SRT，按实测时长回填分镜；通过录前检查后再制作定时动作。
3. 按同一条时间线驱动画面与字幕，试录最复杂的镜头，再录全片。
4. 解码最终 MP4，先检查全片能否听懂，再检查主体动作、字幕和声音。

分镜解决「这一幕怎么看懂」，大纲解决「为什么现在要看这一幕」。镜头再精彩，也不能替整片点题。

## 用户只需提供

| 参数     | 说明                                    | 默认值   |
| -------- | --------------------------------------- | -------- |
| **主题** | 视频讲什么                              | （必填） |
| **语言** | `中文` 或 `英文`                        | 中文     |
| **声音** | `男声` 或 `女声`                        | 男声     |
| **时长** | `短`(1分钟) / `中`(2分钟) / `长`(3分钟) | 中       |

**示例对话**：

> 用户：帮我做一个介绍 Rust 语言的视频，英文女声，短一点

> 用户：做一个关于光合作用原理的科普视频

> 用户：帮我介绍一下文艺复兴时期的绘画艺术，中文女声

> 用户：Make a video about Japanese tea ceremony, English

就这些！场景编排、旁白撰写、视觉设计全部由 AI 自动完成。

## 工作流程

### 第 1 步：收集需求

只问用户**主题**。其他参数有默认值，用户不提就不问。

### 第 2 步：先定讲解大纲，再写分镜和旁白

先核实用户给的材料，把明确指定的要点列全。用一句话定目标：「讲给谁听？看完能解释、判断或做什么？」在开始制作前，把**直白的主题、学习目标、有顺序的大纲和一句收尾结论**简短发给用户。已有大纲就沿用，不让用户再填表；除非要求先审稿，发出后继续制作。

大纲用观众的问题组织，不用场景名称充数。每段写一句回答，并想清楚：观众有了这个答案，为什么还需要下一段？概念课可以由区分到机制再到应用；只讲一个原理时，一个问题、一次演示、一个解释就够，不必凑章节。

例如介绍 AI 智能体，「日历 → 邮箱 → 柱图」是素材清单，不是大纲。可以让同一份会议纪要贯穿三个问题：「谁决定下一步？」（用预设分支对照依据回执改查转写）→「它靠什么做到？」（用刚才的操作解释模型、指令、记忆、知识和工具）→「它何时继续、何时停？」（拿到转写就起草，缺收件人就停下来问）。这样第三段回答的是第一段留下的问题；不必另教观众读一张无关的图。

把大纲变成观众实际听到的讲解：

1. **开头点题并指路。** 在开头一两句里点名对象、提出核心问题。多要点课程再用一句话带出顺序；可以边演示边说，不必先放目录页。比如「这期讲 AI 智能体。拿一份会议纪要，看它和预设流程哪里不同、靠什么做事，又为什么有时该停下来问你。」只写在文件名或片名里不算点题。
2. **正文沿着问题推进。** 先确定本段要解释的事实，再按下文选拍法。把动作、观察到的结果和它说明的道理连起来；换段时用上一段的发现引出下一问。另换案例只有在能说明原例解释不了的东西时才值得。
3. **结尾回答开头。** 给出观众能带走的一句判断或能自己做的一步操作。不要只重念章节名，也不要用一个新术语或下期预告代替答案。

**配音前试读：** 隐去文件名、画面和制作笔记，只连读实际旁白的开场、各段首句与结尾。能否说出主题、讲解顺序和答案？再对照用户指定的要点，逐项指出哪段真正解释了它。缺一项就先改稿，不合成语音、不做定时动画。这里判断讲解顺序；镜头有没有提供证据，另在第 4 步验证。

#### 同一个事实，能拍成几部不同的片？

从大纲中挑一处需要看见证据的事实，用一两句话各试两三种拍法：谁在看？起初以为什么？哪一个看得见的动作会改变这个判断？如果几个答案只是同一张图换颜色，它们还是一个点子。可以向戏剧、魔术、手工、舞蹈或日常小事借一种讲法，也可以自己发明一种；这些不是轮流打卡的选项。

比如讲「月球为什么总以近乎同一面对着地球」，可以拍成**双机位舞台戏**：舞者胸前别一朵红花，绕场心走一圈，始终朝向场心。场心的镜头一直看见花，头顶的镜头却看见肩膀的朝向转过整整一周。也可以拍一个**故意演错的纸偶实验**：先让纸月亮绕瓶盖走一圈，全程让画着脸的一面朝窗户；走到瓶盖背面时，瓶盖上的小镜头只看见了纸偶的后脑。倒带，请观众想办法让那张脸留在镜头里，再演一遍。两种拍法靠不同的发现讲同一个事实，不是给天体模型换背景。

选那个既让人意外、又能让观众事后说出「原来是因为这个」的点子。把其中最值得记住的一幕写成能拍的动作，再选 2D、Three.js、实物或混合媒介。想象可以改写视角、尺度和时间，不能悄悄改写事实；比喻会误导时，切回实物、数据或准确示意。用户给了脚本或品牌，就在它留下的空间里发挥。不必展示备选，也不必每镜都出奇。

#### 逐镜选择表现手法

| 观众需要看懂什么 | 首选 | 镜头怎么拍 |
| --- | --- | --- |
| 内外、遮挡、装配、地形、尺度或空间路径 | **直接用 Three.js 真 3D，无需用户点名** | 产品先看完整轮廓，再沿装配轴拉开；地形先俯视定位，再降到侧面揭示高差。镜头移动必须揭示原来看不到的信息。 |
| 光路、流场、轨迹、群体变化 | Three.js 曲线、实例化网格；平面变化用 Canvas 2D | 先跟随一个样本，再拉远看整体；颜色只编码一个变量，并保留方向或形状线索。 |
| 精确数值、文字、代码、操作步骤 | SVG / DOM / 实际界面录屏 | 固定坐标轴，直接标值；只高亮正在讲的行。不要让观众从透视柱形图猜大小。 |
| 人物、地点、艺术品或实物外观 | 获准使用的实拍、图片或模型 | 从全貌切到证据细节。示意模型不要冒充真实照片，演示数据不要冒充实测。 |

可以混用：3D 讲结构，屏幕空间的二维标注讲名称，最后用静止剖面让观众读数。用户指定画风时优先遵守；不要把旋转卡片或粒子背景当成主体的三维建模。

选中三维镜头后，读 [Three.js 镜头与试录手册](references/THREEJS.md)。可复制的[棱镜样例](assets/prism/src/index.html)包含两镜、语音配置、定点预览和录制入口；复用它的时钟和资源加载方式，不必沿用它的美术风格。

#### 声音预设

| 用户说的 | language | voice                  | voiceRate |
| -------- | -------- | ---------------------- | --------- |
| 中文男声 | `zh-CN`  | `zh-CN-YunxiNeural`    | `-5%`     |
| 中文女声 | `zh-CN`  | `zh-CN-XiaoxiaoNeural` | `-5%`     |
| 英文男声 | `en-US`  | `en-US-GuyNeural`      | `+0%`     |
| 英文女声 | `en-US`  | `en-US-JennyNeural`    | `+0%`     |

#### 时长 → 场景数量参考

| 时长 | 总秒数   | 建议场景数 |
| ---- | -------- | ---------- |
| 短   | 50-70s   | 4-5 个     |
| 中   | 90-120s  | 6-7 个     |
| 长   | 140-180s | 7-8 个     |

这是旁白分段的软目标，不是页数或机位数。一段旁白可以从全貌切到细节，一个动作也可以跨过两段旁白；读表、看代码或比较笔触时，可以留在同一机位。用户说「不超过 60 秒」时，在配置顶层填 `"maxDurationMs": 60000`；不能交付一条 80 秒的视频来替代。

#### 给本片定一个视觉方向

从选中的拍法出发，决定什么要一直认得出来，什么可以大胆改变。比如舞台可以切成真实月面，花的位置接到同一处环形山，观众就跟得上。沿这条线定素材、构图、字体和色彩；用户给了参考图时以它为先。这些是制作笔记，不是屏幕文案。

### 第 3 步：生成 video-config.json

在项目工作目录中创建 `video-config.json`。

**重要**：将文件放在项目工作目录中（与 `src/` 和 `output/` 同级）。

#### video-config.json 最小必须字段

构建脚本只依赖以下字段：

```json
{
  "title": "视频标题",
  "voice": "zh-CN-YunxiNeural",
  "scenes": [{ "narration": "旁白文字", "duration": 10000 }]
}
```

| 字段                 | 类型   | 必须 | 说明                   |
| -------------------- | ------ | ---- | ---------------------- |
| `title`              | string | 是   | 视频标题               |
| `voice`              | string | 是   | edge-tts 声音名称      |
| `scenes`             | array  | 是   | 场景数组               |
| `scenes[].narration` | string | 是   | 旁白；空串表示整镜静默 |
| `scenes[].duration`  | 整数   | 是   | 正数，单位为毫秒       |
| `maxDurationMs`      | 整数   | 否   | 用户指定的全片时长上限 |
| `language`           | string | 否   | 语言代码（默认 zh-CN） |
| `voiceRate`          | string | 否   | 语速（默认 -5%）       |
| `voiceVolume`        | string | 否   | 音量（默认 +0%）       |

自定义字段只在动画需要时添加。例如按当地时间触发实验操作；也可以直接在 HTML/JS 中编排，不必给每段造一份视觉配置。参见[配置契约和示例](references/CONFIG-SCHEMA.md)。

### 第 4 步：先看连续分镜，再看单帧

> HTML 是摄影棚，不是要观众操作的网站。先构图，再写动效；除非正在讲真实软件界面，不要让导航、按钮、角标和面板占据成片。

拿核心段落先做一小条粗分镜，可以是草图、占位几何体或界面状态。按播放顺序看，再问：只给最后一张图，会丢掉哪条有用的信息？例如用完全相同的机位拍两次筛沙，只换筛网；沙粒落下或留下，就比「筛孔大小影响结果」这个标题更直观。讲绘画时反而可以停在原作上，让观众沿着指尖找到被忽略的细节。不需要为变化而推拉镜头。

再挑信息最密的一帧，用真实素材和最长字幕检查排版。不默认预留常驻页眉、章节号、左侧结论栏或右侧插图区；让主体先占到讲清它所需的位置。系列标识或对照布局有用时保留。

- **构图**：先放观众应该看见的东西，再放指向它的标注。把相关文字贴近对象，沿同一条边对齐。把标题暂时遮住，如果只剩几个框、看不出在讲什么，就换成实物、剖面、地图或有刻度的图，再决定是否需要框。
- **文字**：标题、标注、字幕分工，不把旁白另抄一遍当正文。全片用一到两套有中文字形和本地后备的字体；英文代码才用等宽。以 1920×1080 试排时，字幕可从 48–60 px 起步，按意群断行，最多两行；放不下先拆字幕或分镜，不把字一路缩小。
- **色彩与光**：从素材取底色与文字色，把最强的明暗或色彩对比留给当前主角。画光谱可以绚丽，比较数值却只需突出差值。用灰度看一眼：如果只能靠颜色区分，再加形状、位置或直接标注。
- **安全区**：以四边各留约 5% 为起点，给底部两行字幕单独留位；主体可以出血，关键信息不出血。字幕压在复杂纹理上时给文字局部托底，不用一条永远在场的黑色横幅。

实际打开这张静帧：先缩到约 480×270 看主体和字幕，再用原尺寸看换行、字形和遮挡；不通过就改构图。此时不必给动画定秒数。

### 第 5 步：搭建环境、合成语音并校验时间线

在项目工作目录中运行以下命令：

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
# source .venv/bin/activate

python -m pip install "edge-tts>=7.3.1,<8" playwright
python -m playwright install chromium
```

同时确保 FFmpeg 和 ffprobe 已安装并在 PATH 中可用。只做二维镜头不需要安装 npm 或 Three.js。

```bash
python <skill-path>/scripts/generate_tts.py video-config.json
```

每个有旁白的镜头生成同编号 MP3 和 SRT，写入 `assets/audio/`。例如「留两秒让观众猜」写成 `{ "narration": "", "duration": 2000 }`；它占镜头编号和片长，但不需要音频或字幕文件。

用 `ffprobe -v error -show_entries format=duration -of default=nw=1:nk=1 assets/audio/scene_1.mp3` 测每段声音（秒），与该段 SRT 最后一个结束时间取较大值，再加所需停顿，换算为毫秒回填 `duration`。构建器只会补静音，不会把过长旁白缩进镜头。遇到 TTS 403，先用当前虚拟环境的解释器核对客户端版本并试合成一句，不要覆盖全局环境。

```bash
python <skill-path>/scripts/build_video.py --check video-config.json
```

此命令不需要动画页面，不启动浏览器。如果某镜声音或字幕超过时长，先检查单位、停顿和分镜；全片超出硬上限时，优先精简旁白或删减镜头，再合成并复查。不要截字、截字幕或擅自放宽上限。更换声音或语速也要重新测量。

### 第 6 步：按实测时间制作动画，试录最重的一镜

在项目的 `src/index.html` 制作入口。简单镜头可内联 CSS/JS；三维镜头用本地 ES 模块、模型和纹理。分辨率固定 **1920×1080**。

遵守 [HTML 动画合约](references/HTML-CONTRACT.md)：在 `?headless=true` 下等配置、字幕、字体和必要素材就绪，画首帧，用同一个 `performance.now()` 设置播放起点和 `window.__playbackStartedMs`。按 `scenes[].duration` 驱动主体和 `#subtitle-bar > #subtitle-text`。有旁白才读 `../assets/audio/scene_N.srt`，手动有声预览才播放对应 MP3；静默镜清空字幕。加载失败报告具体路径并设置 `window.__playbackError`，不发起播信号。

让观众知道此刻该看哪里。请求返回，可以沿原路带回结果；两个机位互相作证，就让它们同时动。静音连看开场和揭晓，若意外只来自一句「其实不是这样」，就把证据拍进画面里。将揭示动作对齐实际 SRT 中对应的词句，再留出看懂的时间。

在实际录制环境试录资源最重的 3–5 秒，查主体是否运动、字幕是否挡图。另把最容易做成幻灯片的核心段落从铺垫连放到结果，静音并暂时遮住解说性标题和字幕（保留作品、代码、数值等证据）。能指出「哪一步让人看出了什么」才算讲清；若只能看见转场或装饰运动，回到分镜改拍法，不是加动画。两项可以使用同一段录像。

### 第 7 步：构建视频

```bash
python <skill-path>/scripts/build_video.py video-config.json
```

此命令会：

1. 重新检查时间线和有声镜头素材，确认 `src/index.html` 存在
2. 启动本地 HTTP 服务器
3. 在无头 Chromium 中录制动画（等待 `__playbackStartedMs` 信号）
4. 从原始录像的片尾校准帧确定实际播放起点
5. 按镜头顺序补齐并拼接音轨，空旁白生成等长静音
6. 按校准起点裁切并编码 MP4，不保留校准帧

最终 MP4 文件位于 `output/<timestamp>/video.mp4`。

### 第 8 步：交付给用户

先看**编码后的文件**，不要把浏览器预览或构建返回成功当作验收：

先像第一次看到这条片的人那样，从头连续播放，不看文件名、简介或大纲。开场能说出「这期讲什么」吗？进入下一段时，能说出它接的是上段哪个问题吗？结尾能用自己的话回答开场吗？对照第 2 步向用户展示的大纲：若答案只能从制作笔记里找到，回到旁白和段落顺序修改，再导出；补一张标题卡不能代替这项检查。

1. 用 `ffprobe -v error -show_streams -show_format -of json video.mp4` 检查 H.264、1920×1080、AAC，以及时长是否与分镜总长相符（末帧/音频编码可有小幅舍入）。
2. 在有动作的一镜，取两个不同进度的编码帧，确认**主体区域**发生预期变化，而不只是字幕变了。再抽查开头、中段、结尾各一处有台词的画面；检查字幕可读、没被裁切，揭示点与所讲的词对齐。
3. 听开头和跨镜头的几秒声音，核对音色、不截字、不串场。失败先修再导出；通过后报告输出位置、分辨率和实际时长。
4. 从最终 MP4 连看上一步选的核心段落：观众能否从动作、对照或细节本身找到证据？再把开头、中段、结尾并排看；若始终是同一版头下换标题配插图，且这个版式没有比较或定位作用，回改分镜。像素变化证明录制没冻结，不证明这段讲解成立。

## 时长计算规则

初稿可按中文每秒约 4 字、英文每秒约 2.5 个单词估算。最终按第 5 步实测，不为凑时长填充无意义动画。

## 使用技巧

- 视频总时长建议控制在 3 分钟以内，效果最佳
- 旁白语气要自然、口语化，避免机械感
- 每个场景只传达一个核心要点
- 根据主题选择配色和动画风格，让每个视频都有辨识度
- 分辨率固定 1920×1080，所有布局按此设计
- 优先使用可随项目复制的本地资源，录制时不要临时请求 CDN、远程字体或图片
